# 提案：语义臂切块稀释的两个量尺（B4）——doc-oracle 与 chunk 尺寸 ablation

> 状态：**proposed**（2026-11-13）。
> 来源：`research/2026-11-external-ir-bench.md` F2——语义臂召回在、排位被稀释
> （SciFact R@100 0.933 / nDCG@10 0.660 vs 论文整文档 0.734；NFCorpus 同形 0.858/0.338/0.367）。
> 定位：**只量不改**——两把量尺把 F2 缺口拆成「候选池排位问题」vs「切块粒度问题」，
> 为未来任何首段排序机制（含 CCH 对无结构 txt 的形态）给上界证据。

## 1. 问题

-2.9~-7.4 点的语义臂缺口在首跑里只能整体归因于「512-token 切块 + doc 首现折叠」。但同一句话
至少藏着两个可分离的成分，处置方向完全不同：

- **C-a 首段排位**：正解 doc 的证据 chunk 在候选池内、但排位不足（多 chunk 同 doc 平权竞争、
  语境缺失）——rerank-depth 已部分可治，CCH 类语境前缀治本（结构化源已兑现，txt 是盲区）；
- **C-b 切块粒度**：512/64 窗本身切碎证据（跨窗证据、标题-正文分离）——换粒度才能治，
  但 chunk 粒度是回源定位的产品契约（T13 坐标），动它是重大裁决。

没有量尺之前，任何「加大 chunk / 上下文化」的主张都是拍脑袋。

## 2. 目标 / 非目标

**目标**
1. **量尺一（doc-oracle，零额外机时）**：B2 的 rerank-depth 100 曲线即候选池排位上限——
   depth100 nDCG 与 hybrid R@100 的比值量化「池内有货没排上」占比；按基准分列；
2. **量尺二（chunk 尺寸轴，一次 25min 小桶重嵌）**：scifact 对照桶 `token-window 1024/128`
   跑 semantic/hybrid 臂——量化粒度翻倍对 F2 的边际贡献；
3. 产出并排进 B0 基线：F2 = C-a(量尺一) + C-b(量尺二) 的归因表。

**非目标**
- **不改默认 chunk 尺寸**——T13 坐标粒度是契约；1024/128 只是量尺，改默认需独立裁决 +
  全量波次（本提案明确不申请）；
- 不做整文档嵌入（论文口径追平）——违背 chunk 回源语义（roadmap §3 明确不做）；
- 不做 late chunking / LLM 上下文化（R2 轮三重否决维持）。

## 3. 方案选项

| 选项 | 裁决 |
|---|---|
| **A. 两把量尺并行**（oracle 顺 B2 + 一次小桶重嵌） | **采**——合计 <1h 机时，产出直接路由「下一轮语义臂机制要不要立项」 |
| B. 直接上语境前缀 for txt（首行标题启发式等） | 否——txt 无结构信号，启发式即 R7 轮退役的形状启发式同族；量尺先行 |
| C. 只跑 oracle 不跑尺寸轴 | 否——oracle 只见 C-a，C-b 无证据，粒度裁决仍靠拍脑袋 |

## 4. 关键取舍

1. 量尺二用 **1024/128**（粒度×2、重叠同比例）而非极端值——边际信号清晰且不碰 gte 位置
   编码衰减区；
2. 对照桶命名进 B0 口径（`scifact-c1024`），避免与主桶混跑；跑完保留（后续 B3 若立项，
  analyzer+粒度交互可复用）或即删（省 2GB 盘）二选一在执行时定；
3. oracle 的解释边界：depth100 仍受 topK=10 返回约束，nDCG@10 口径下 oracle 是「重排上限」
  不是「排序上限」——README 脚注钉死，防过度解读。

## 5. 依赖与风险

- 依赖：B0（口径）；B2（depth 曲线产出 oracle 列）；量尺二独立可先跑；
- 风险：①1024/128 与 512/64 的 gte 位置编码行为差异混入粒度信号——单变量原则下接受
  （同一模型同一 ctx，窗口策略即被测轴）；②oracle 与量尺二的归因和 ≠ F2 全额（交互项）——
  归因表设「交互/未解释」残差列，诚实记录。
