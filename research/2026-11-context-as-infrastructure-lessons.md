## 0. 论文实际说了什么（含传播稿未讲清的细节）

论文系统：Agentic 检索 Harness（Search→Read→Reformulate→Stop 循环，MiniMax M3 作答），
检索面只有 BM25 + grep + claim 文本词法腿，**无向量索引**（§2.1："no dense-retrieval leg
anywhere in this paper"）。grep 的引擎级实现（ES regexp 下推 / Infinity n-gram 圈候选 +
正则验证）出自传播稿非论文，记为工程线索。主要数值（除标注外 FRAMES，N=200，单次运行；
决策门两行为更小子样本臂均值，BrowseComp-Plus 为规模检验）：

| BrowseComp-Plus（规模检验）| 85.0%，~3.0×10⁶ tok/题 | §8.7 |
| 证据命中时 token | **-91%** | §8.3 |

传播稿漏掉或模糊的四点，对照时必须带上：

1. **延迟不是免费的**：证据替换省 token 但延迟约三倍——论文自己的服务形态（证据页小 →
   轮次多）。决策门是补救不是红利本身。
2. **2% 盈亏平衡是无穷期渐近值**：有限部署（Q 小 / c 大）门槛显著抬高，"编译一切"不成立。
3. **接受率 ≠ 正确率**（§8.6）：p_h 只是门接受率；false-accept 率 φ 需 100–400 条分层标注
   审计才能钉住（100 条 @10% 真率 → 置信区间 4–16%）。论文自己未测 φ。
4. **部署账本全空**（Table 2）：ontology/graph/wiki/timeline/memory 的"商业价值"全部
   "no measured effect"——论文用预注册 + 空结果列把它们与实测机制严格分开。传播稿的
   "商业意义"论述是愿景不是观测。

## 1. 适用边界（前提修正后的重画）

vectorfs 的真实定位是**中间形态**：单发检索管线（`ops_xvf.rs:1268` 起，无改写/多跳循环，
零 LLM 查询纪律），但主要消费者之一是自主 Agent（MCP 面，`mcp.rs:678-727` 包装同一
`/x-vf/Search`）——**Agent 消费者自带循环，vectorfs 是循环内的一个工具**。

| 论文结论 | 依赖循环？ | 对 vectorfs 判定 |
|---|---|---|
| BM25+grep 达 85%/91% | 是（Agent 改写填平词汇鸿沟）| ❌ 不转移：vectorfs 自身仍须单发保召回；但见 §2 轮数重定价 |
| "dense leg 降准确率" | 是（两套排序让循环调和）| ⚠️ 半转移：hybrid 调用在服务端融合成**一份**列表，论文 design rule (6) 担心的调和成本在结构上已被 fusion 消化——不构成砍语义臂的理由；但**边际价值排序对 Agent 段翻转**（§5） |
| "chunk 只是召回单位" | 是（边界失误可改写救回）| ⚠️ 半转移：chunker 精化停止加投；chunk 文本仍是 Agent 的阅读单位与 claim 抽取单位 |
| 结构工件不涨准确率 | 部分（grep+读=按需索引，静态分区竞争不过下一查询）| ✅ 病理可转移：结构词不是证据、抽取误差复利、有损压缩文本交模型猜必败 |
| Token 经济学（claim-evidence）| 弱 | ✅ 转移且动机直接成立（Agent 上下文即稀缺资源） |
| 工程纪律（通道隔离/零命中/条件成本测量）| 否 | ✅ 完全转移 |

## 2. 核心综合：循环轮数是 vectorfs 对 Agent 的计量单位

论文的循环不是免费的：FRAMES 325k tok/题、BrowseComp-Plus ~3M tok/题——"Harness 解决
准确率"是拿轮次和 token 堆出来的。由此：

> **vectorfs 对 Agent 的产品价值 = 帮循环省掉的轮数。九实验的病（正解沉 rank 27）对单发
> 消费者是"查不到"，对 Agent 消费者是"多烧 N 轮或中途放弃"。R1–R4 未被 Agent 前提贬值，
> 而是换了更硬的计量单位：首轮命中 = 省整轮 token+延迟。**

定位论纲而非已测事实：论文测的是自家 Harness 的轮次成本，九实验测的是单发排序——"首轮
命中 ⇒ 省轮"的转换率尚无循环级测量（应进 R6 的 Agent 段形态）。

推论：改善首轮命中质量的项（R2 的 rerank 前缀补课，§3.2）在 Agent 前提下价值上升。

## 3. 对已交付四项的逐项裁决

### 3.1 R1 锚词门控词法——哲学同盟，两处补课

同盟：论文 §6.2 把"词汇失配"列为首要失败原因，工具是 BM25/grep/claim 检索，语义交还模型。
R1 的 df 探针门控正是"词法提供不含语义偏差的定位原语"的实现。旁证（传播稿转述 OpenAI、
非论文内容，线索级）："Agent 极爱带引号的精确查询"——与 `anchor_candidates` 引号段优先
（`lexical.rs:209-286`）同向。

- **补课一（bug 级）：门控零命中无回退**。探针失败降级 ungated（`ops_xvf.rs:1648-1658`），
  但 `search_gated` 返回空（锚词块全被 filter 挤掉等）时原样透传（`ops_xvf.rs:1670-1695`）。
  hybrid 模式语义臂兜底；**keyword 纯模式下一步门控空 = 全灭**。论文零命中原则（§6.2：
  零命中是工具属性非语料事实，引擎须解释零、走完回退阶梯，模型才可下"语料沉默"结论）
  正中此害——Agent 消费者会把 0 命中读成语料无答案。修法升维为**机制 3 退化阶梯**
  （§6）：gated 空 → 回退 ungated + response note 报告锚词与松弛动作，为阶梯首实例。
- **补课二（测量纪律）**：按论文敏感性教训，该精细测的是**锚词误判频率**（正解块恰缺
  锚词 / 用户真想搜高频词的查询占比），不是成功案例的排名改善。进 R6 预注册指标。
- 附带升级：R1 的 `anchors` 观测字段（`ops_xvf.rs:1918-1920`）对 Agent 从可观测性升格为
  **改写反馈信号**——锚词判定可见，Agent 可加引号/换词重述。

### 3.2 R2 CCH 前缀——双重背书，一处交付缩水

- **背书一：PageIndex 之死与 R2 不同机制**。论文 PageIndex 负退化机制（§8.2：抽取层级
  残缺错位 + 错误分支比开放搜索更贵 + 自信路由集中查询）全是"LLM 拿有损目录做路由"的病。
  R2 前缀只进嵌入输入（`pipeline/embed/mod.rs:87-102`），检索仍全量匹配，无路由面。"TOC 被消费
  而非被索引"（`pipeline/mod.rs:356-360`）+ T12 默认排除 toc/legend（`ops_xvf.rs:810`）
  与论文"结构不是证据"同向。
- **背书二：通道隔离**。论文 §3.4 把"原文/派生严格分离、派生永不写回"列为监管前置条件，
  点名这是 LLM 维护语料库最常见失败。`x-vf-chunk-text` 永远原文（`ingest/mod.rs:2496-2500`）
  正合此律。
- **缩水（doc-code delta，需裁决）**：研究文档 R2 承诺"三路普惠……重排输入同带前缀"
  （:64-73），但重排候选文本取自 `x-vf-chunk-text` 原文（`ops_xvf.rs:1787-1798`），
  `embed_prefix` 不落盘——**reranker 从未见过前缀**。九实验 F（reranker 被方法论段骗）
  恰是 reranker 缺章节语境的病。修法升维为**机制 1 语境通道一等化**（§6，权限矩阵：
  嵌入/rerank 入，FTS/回源不入，metadata 可见），落盘 `x-vf-context-header` 字段后
  rerank 候选文本 = header + 原文。原两案作为机制下的实现取舍：(a) 落盘独立 `x-vf-embed-prefix` 元数据字段
  （不入 FTS、不回源；需重跑 ingest 盖章，无需重嵌）；(b) 查询期重算前缀拼进 rerank
  输入——但章节标题表（`Part.sections`）是切块期通道、未持久化，需新增小型持久面或
  回源重解析。两法均零重嵌，直击实验 F 病灶。
- **警示**：论文"抽取误差复利"（95%/决策 × 分支 8 → 10⁵ 文档端到端 ~75%，解析模型非实测）
  对 R2 的适用形式是**前缀错标率**——TOC→章节映射是扁平最近邻、无层级重构
  （`windowing.rs:92-132`），跨章窗口拿前一章标题。单层不复利，但错标污染嵌入。R2 验收
  应加：抽样审计前缀-窗口对齐率。

### 3.3 R3 深度解耦 + fusion-overfetch——深度红利的方向性类比（非直接证据）

论文 §8.4（方向级、单次运行）：claim 检索的**锚深** 10→20 提升命中、30 无进一步收益；
保留 topN=20、k=100；"召回来自锚深与两词法腿之并集，不来自更用力地搜"。这是另一参数、
另一系统的方向性类比——vectorfs 的 `fusion-overfetch`（缺省 1，`pipeline/config.rs:642-647`）
是每臂候选池倍率。**2 作为 preset 候选值**（毫秒级成本），实测定夺进 R6，与既有研究文档
"Qdrant 深度红利"表述同级。R3a 深度解耦被同段"深度红利要后段用得上"支持。weighted RRF
调优的提醒引论文原句："召回不来自更用力地搜"——别指望重排/加权救召回。

### 3.4 R4 per-source 配额——方向对，反向警告明确

论文页组成消融（§8.4）：**计数截断伤召回**——页帽 16/32 使晚段相关项被删，加倍不减轮次
只加单轮成本；替代方案是行级决策过滤。R4 是纯计数配额且**无回填**
（`ops_xvf.rs:1742-1769`），同类风险：挤占源的真正相关块排在配额后直接消失。缓解：
配额在 rerank 前（正确——不浪费重排预算）；教科书 794 块单源挤占是真病
（research :87-88）。**建议**：R6 把"配额无回填的晚位损失"列为预注册测量项；若实测有损，
考虑软配额（配额外降权不删除）或回填语义。

## 4. MCP 工具契约的三块缺口（Agent 前提下的一级事项）

MCP 现暴露 9 工具：`search / query_vectors / get_vectors / list_*` ×3 + 写 ×3
（`mcp.rs:1227-1250`）。读完即断头——`vf chunks` / `vf chunk show --around` 是 CLI 独占。
对照论文 §6.2"按失败原因组织工具"：

1. **锚定深读缺失**（localization at scale 的标准工具）：Agent 命中某源第 37 块后无法在
   MCP 读 36/38 块。
2. **grep/phrase 缺失**：DCI / grep-all-you-need / Pi-Serini 文献链共识——胜任 Agent 用
   grep+读胜过向量检索。filter 语法无 regex/contains（`filter.rs:6-7`）。

两缺口合并升维为**机制 2 内容寻址读平面契约**（§6）：`locate / read / enumerate` +
零命中解释，作为 chunk-key 地址空间上的一等契约，CLI 与 MCP 双面。
3. **零命中协议缺失**：note 只覆盖 src-name 打错（`ops_xvf.rs:1891-1908`）。缺：门控空
   回退（§3.1）；note 升格为"回退阶梯已试过什么"的控制消息。

另有：search 未暴露 rerankDepth/perSource——Agent 不调旋钮，**缺省即产品**（§6 裁决清单）。

## 5. R7（新提案）：claim-evidence 摄取技能——主力消费者经济学

论文唯一强正收益机制（准确率中性 + token -38%），落地形态与 vectorfs 基建高度契合
（claim 召回的路由方式为 vectorfs 侧设计决策，见下表）：

| 论文构件 | vectorfs 已有对应物 |
|---|---|
| 叶 = 原子声明 + 逐字引用 + 源偏移 | T13 坐标（`ingest/mod.rs:2482-2495`）+ 内容寻址 chunk key |
| 类型化工件 / 版本 / lineage | T12 chunk kind（加 `claim` kind 即入治理面） |
| claim 召回（E1，论文为**纯词法** BM25 over claim text） | vectorfs 侧选 hybrid 接入（措辞差异场景；**设计决策**非论文主张，传播稿亦建议 hybrid）+ R4 配额作 fusion 新 source |
| 通道隔离（声明可回源核验） | R2 已建好的嵌入/原文通道纪律 |
| 便宜抽取模型 + span-match 验证（"模型提议、原文裁决"） | openai embedder 端点基建可复用为抽取端点 |

服务模式取 **E2（证据替换，论文缺省）**：命中照常返回，`content` 可选投影为该 chunk 的
claims+逐字引用，Agent 先读声明、够用不读原文。**待验证假设**（论文明言延迟代价"是表示
形式的属性而非配置的属性"，§8.4）：vectorfs 的 E2 把声明挂在命中上随一次调用返回，或可
避开论文"证据页小 → 轮次多"的形态——但 miss 时 Agent 仍需一次 `read_chunk` 往返，轮次
代价是否真被消解须实测。回退路径（声明不够 → 精确回读原 chunk）恰是 §4-1 `read_chunk`
的载体，两项互为配套。E3 决策门是消费者侧职责，vectorfs 不做（论文自己把 gate 归 harness）。

三条诚实线：
1. **零 LLM 纪律需显式修订而非绕过**：既有纪律同时覆盖查询期（HyDE）**与摄取期**
   （LLM 上下文化，:42/:103-104 皆明写"违反零 LLM 纪律"）。R7 的 claim 抽取属后者，
   须作为纪律修订案裁决（限定：摄取期、opt-in、span-match 验证兜底、摊销成本显式入账），
   不能宣称"本就不违反"。
2. **有限期经济学**（Eq. 9）：低查询量桶不该编译。默认关，per-bucket opt-in。
3. **只取叶不取树**：carrier tree/wiki/graph 论文全中性或负面，RAGFlow 生产位形里导航
   工具"压根不用"（§6.2）。要的是 claim-evidence 数据形态，不是任何树/图容器。

## 6. 机制优先的补全路线（裁决清单 v2）

**裁决原则**：优先从机制上补全缺口——每个缺口以"不变量 + 通道/契约"的形式进入架构，
打补丁式修复只允许作为机制落地的首实例。原清单三个补丁项（门控零命中回退、rerank 拼
前缀、MCP 加读回工具）据此分别升维为机制 1/2/3 的第一实例。

**R5（Qwen3 模型轴）对 Agent 段降权**（推断非直证——论文原句针对"新增"dense leg，
非"升级"现有嵌入模型）：循环消费者从改写获得语义，嵌入升级的边际收益小（论文："dense
leg adds no signal the loop lacks"）；R5 主要服务 S3 协议面单发段。

### 机制 1：语境通道一等化（derived-context channel）——吸收原"rerank 拼前缀"补丁

> 设计定稿：独立设计代理 + 交叉验证（2026-11-11，双方方案逐点裁决，本节为合并稿）。
> 落地时以 ADR 0007 固化。

- **不变量（权限矩阵）**：嵌入输入 ✓（现状）/ rerank 输入 ✓（新增，治九实验 F）/
  FTS 文本列与 BM25/df 统计 ✗（结构隔离：text 列只读 `x-vf-chunk-text`）/ 回源
  content.text ✗ / 响应 metadata ✓（blob verbatim）+ `location.coord.chapter` 蒸馏 ✓ /
  协议面零新语义（metadata verbatim，ADR 0003/0005 先例）。
- **落地**：元数据键 **`x-vf-chunk-context`**（chunk 族命名、**可过滤**——章节即寻址
  坐标，`$startsWith` 支持卷/章范围检索；不进 nonFilterable 声明 ⇒ 新旧索引零漂移；
  键预算 12 ≤ 50）；单一合成律模块 `pipeline/context.rs`（`compose/at_rest/of` 三函数，
  嵌入与 rerank 两读者共走一条 join，键字面量单一家园 lint）；rerank 候选 =
  context + "\n" + 原文（与嵌入输入同形——交叉编码器评分的文档分布 = 索引编码的分布）；
  `Chunk.embed_prefix` 随同更名 `context_header`；**无新旋钮**（存储键是唯一事实源，
  查询面旋钮不得重释索引态）。
- **迁移**：**`vectorfs optimize --restamp-context`**——只跑 extract+chunk（CPU 段，
  零嵌入：toc-path 桶在旋钮翻转时已重嵌、向量已携带前缀），逐 chunk 校验重算文本 ==
  存储原文后 merge-insert 仅改 metadata（`backfill_text_column` 先例，幂等）；校验
  不过跳过并大声报告；`store-chunk-text = false` 桶拒绝盖章。
- **既有断言的改写义务**：`ingest/mod.rs:4776` "前缀不出现在任何元数据值"改为
  "只在受治键下、永不在 `x-vf-chunk-text`"；全仓 ~6 处 "EMBEDDING INPUT ONLY" 文档块
  改写为"仅模型输入（嵌入+rerank），永不进文本通道"（边界推广非废除）。
- **测试义务**：矩阵每行一个具名测试；rerank 读者用 tiny 交叉编码器精确 logit oracle
  （Σ(id+1)）封闭验证；`flagship_cch` 加 rerank 臂测疗效与 token 预算挤出效应。
- **前瞻**：R7 的 claim 文本/逐字引用以同一通道形态接入（同键族 + 同合成律 + 每消费者
  一行矩阵），不另起存储。

### 机制 2：内容寻址读平面契约（read plane over chunk-key address space）——吸收原 read_chunk/grep 两补丁

- **不变量**：chunk key 地址空间（"向量世界的行号"）上的读操作是一等契约，CLI 与 MCP
  是同一读平面的两张脸（沿 ADR 0004 双面先例；S3 协议面不动）。四个动词：`locate`
  （phrase/regex 模式定位 → keys + spans；FTS phrase/词法圈候选 + 内存正则验证，照
  RAGFlow 工程纪律绝不全表扫——Lance phrase 能力需 spike 确认）/ `read(key, around)`
  （点读+邻域，字符帽沿用 CLI 语义）/ `enumerate(prefix)`（CLI 已有 `vf chunks`）/
  零命中解释（每个工具的结构化"为何零 + 试过什么"，论文零命中原则）。
- **定位**：论文 §6.2"按失败原因组织工具"的契约面——锚定深读与 grep 是胜任 Agent 的
  核心动词；同时是 R7 E2 投影的回退路径载体（声明不够 → `read` 原文）。

### 机制 3：查询约束退化阶梯（restrictor degradation ladder）——吸收原"门控零命中回退"补丁

- **不变量**：任何可能产出空集的查询期约束（锚词 MUST、编译 filter、未来的证据门）必须
  定义松弛级，且响应必须报告已施加/已松弛的阶梯——控制消息，永不作证据引用（论文零命中
  原则："零命中是工具属性不是语料事实"）。
- **落地**：R1 门控空 → 重跑 ungated → note 报告锚词与松弛动作，为第一实例；T15 的
  src-name note 并入同一报告面。与纯补丁的差价仅"报告不变量"一层，一并落。
- **前瞻**：R7 的证据门（若做服务端预取）天然落入同一阶梯。

## 7. 方法论教训（写进 R6 规格）

1. **报条件切分不报均值**："38% 均值背后是 91% hit 和 1.9% miss"（§9 design rules）。
   R6 报告格式：按查询形态（结构词洪泛/锚词/常规）分列，不聚合。
2. **预注册目标 + 空结果照登**（§5.3 Table 2 后三律：分析单位是语料集非单答案；同查询量
   shadow 对照；目标先写后跑，null 报 null）。
3. **单次运行 = 方向而非估计**：论文结构消融各跑一次敢标"中性"，同时明写"不排除低于
   分辨率的小效应"。九实验同认知地位，表述对齐。
4. **接受率 ≠ 正确率**：任何门控上线前配 φ 审计（100–400 条分层标注）。R1 锚词门控
   已缺省上线（`pipeline/config.rs` 默认 true）——φ 审计对其是追溯义务，即 §3.1 补课二。
5. **shadow 先于 enforcement**：阈值不能在它拒绝的查询上调（反事实不可观测）。
